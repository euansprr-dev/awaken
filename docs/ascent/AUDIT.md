# The Ascent: verified audit (build/awaken-v1 at 41492e5, 24 Oct 2026)

Three read-only code audits, condensed. Paths are under src/main/java/dev/awaken/ unless they start with docs/, src/
or tools/. Everything here was checked in code unless marked "doc only".

## Movement today

**Slots.** A MOVEMENT power fits slot 5 (Left Alt) or any active slot, Z/X/C/V (PowerType.java:52,175-182). There is
no "Blink" power and no "Glide" power: Blink is Dash variant 1, Glide is Hover variant 2 (the proposal
docs/proposals/awakened-body.md is wrong on this).

**Shared.**
- Fall safety is a NO_FALL buff (Moves.java:125-128; PowerEvents.java:116-119,173-177).
- A refused prediction zeroes velocity on both sides (Casting.java:53-66).
- **Visuals and sounds are not predicted; only the pose is** (FxClient.java:121-134), so speed lines arrive one round
  trip late.
- Every power sound is a remapped vanilla event (src/main/merge/powers/assets/awaken/sounds.json).
- FX use vanilla render types plus power_fx sprites; there are no custom FX shaders.

**Awakened Body** (dev.awaken.body):
- **Unlock rule:** awakened && rank ≥ the move's rank (Body.java:34-37). Roll E, Tactical E, Slide D, Mantle C
  (Move.java:11-14).
- **Numbers** in BodyRules.java:26-76: tactical ×1.25 for 60t with a 7t double tap; slide 14t from v0 0.38;
  mantle ledge 1.1–1.6; momentum hits +0..30%.
- **Prediction:** client prediction in MovementInputUpdateEvent (client/ClientMoves.java:75-122); server checks
  against recent history (BodyServer.java).
- **Camera** (client/BodyCamera.java:41-116): roll and pitch in ViewportEvent.ComputeCameraAngles, FOV, hand
  transforms.
- **Assets:** PAL clips with `_bent` twins (player_animations/body_moves.json, generated by
  tools/art/specs/body_moves.py), own sounds (BodyContent.java:32-36), and the awaken:body_dust particle.
- **Sync:** other players see moves through the Seen payload (BodyServer.java:238-252).
- **Hooks:**
  - core/api/MovementHooks.java:14-85 (sliding, tacticalSprinting, mantling, lastMoveTick, slideDirection,
    castStarting);
  - powers/MoveTwists.java:26-135 (a cast within 10t of a move refunds 10%; family twists mid-slide).
- **This is the best-feeling movement in the game: build on it.**

**Feel tools** (all respect the camera-shake, flash and FX-level settings):
- FxScreen (powers/client/fx/FxScreen.java): tint flash, impact-frame post chains power_fx_impact_0..3, fovPunch,
  kick (pitch, yaw, roll), and speedLines (a GUI layer of 18 fills, not a shader).
- CombatFeel: shake and hit-stop.
- Lens: LensClient.override / tear / ritual (lens/client/LensClient.java:163-200), used only by the Ritual.
- Power post chains: flow, foresight, overload, third_eye, cloak, void.
- **Camera Overhaul is in the pack with no compat code, so four camera sources stack.**
- **PAL:** only PalCasts imports it (two layers: casts at priority 1500, body at 1600). **There are no clips for
  flight, glide, fall, grapple, wall-run or any airborne motion.**

**Carillon's Runner prototype** (branch carillon/spike-runner, report docs/carillon/spikes/S3-runner.md on that
branch; code body/RunnerRules.java, RunnerServer.java, client/RunnerMoves.java, RunnerTests.java):
- **Proven:** wall-run (about 2.3 blocks lower over 10.5 blocks), wall-jump chains, ledge hang, shimmy, ledge jump.
- **Server checks:** history-based checks gave 0 rubber-banding at 150 ms; "now" checks refused every wall jump. A
  jump-held trigger fires off 1-block steps; a press-in-the-air trigger fixes that. A hang never trips the floating
  kick.
- **Open:** after an upward grab the server's Y sits 0.58 low. Coyote time and the buffer were never measured.
- **Its own verdict:** stiff, silent, poor first-person hang view, "an add-on, not a mod".
- **Spec:** SPEC §16.3 on carillon/main (wall-run 35t, wall jump +0.42/0.5, four links, ledge hang 1.2–2.4,
  shimmy 1.6 b/s, coyote 3 / buffer 4 / snap 0.3; Wall Stride 80t, grip 50, works on glass and leaves; roll 5°).
  **Wall Stride isn't implemented anywhere.**

**Progression:**
- The starter pool never offers a movement power (Starter.java:44-45).
- Power Cores roll any non-hidden power at or below the core's rank (PowerRegistry.java:48-75). **Flight comes only
  from a random A-rank core.**
- **Movement outside a fight earns 0 mastery** (Mastery.java:25-29,144-147).
- Counters exist (dashes, dash chains, sprint_cm, fall_survived_max, training_laps, kills_airborne). kills_airborne
  excludes flying players (Combat.java:278-280), although docs/modules/powers.md:102 says flying counts.
- Hearth Training Grounds: start gate, checkpoint rings and finish; tick-timed laps with a best-lap ghost
  (hearth/training/Training.java, TrainingGhost.java). The ring's own comment says it suits gliding and flying
  courses.

**Risks:**
1. **Floating kick:** no handling in the repo. The vanilla rule (ServerGamePacketListenerImpl.java:331-339,563-566,
   1222-1230) only kicks a player who can't fly, on a dedicated server with allow-flight=false, with only air around
   them. So any airborne state should grant mayFly while it runs.
2. **"Moved wrongly":** server pushes (Combat.push) never call applyPostImpulseGraceTime.
3. **Mounts and elytra:** powers have no isPassenger or isFallFlying guard (the Body does).
4. **Lucid dreams** set mayfly directly (lucidium/dream/Dreams.java:179,383-384,564-569) and can collide with
   Flight.
5. **Jet Boots** (above/client/JetBoots.java:49-51) climb in open air and may already trip the kick.

## Gates today

- **Generation:** GatePlan (gates/content/GatePlan.java), content version 3. The Director roll is in gates/Director.java:26-147.
- **Counts:** 15 themes, 8 layouts, 14 modifiers, 8 twists, 15 Lords with 3 phases each.
- **Lords** (mobs/def/GateBestiary.java; mobs/entity/AwakenBoss.java): ability kinds SLAM, LEAP, CHARGE, BOLT,
  ARROWS, NOVA, BURST, RAIN, BEAM, BLINK, SUMMON, CLOUD, CONE, PULL, GUST, HEAL, ROOT, FANGS, DECOY, GUARD, LIFT,
  DARKNESS, AURA, FRENZY. **No Lord changes its arena's blocks.**
- **Rooms:**
  - 19 room kinds (world/Room.java:14-17) and 12 shapes.
  - Slots are 16×16 with a 12×12 interior and 4-wide doors (RoomGeometry.java:11-14).
  - Floors sit at Y 200 − 32(f−1) (Cells.java:21-22), and you go down a floor by teleporting through the Seal.
  - Painted in code (GatePainter.paint, a pure function per chunk), dressed by Kit (world/Kit.java:90-196), with
    SetPiece and Pieces (PiecesRooms, PiecesSmall, PiecesArenas, PiecesRitual) chosen per room.
  - **There are no .nbt templates.**
- **Puzzles:**
  - **Only one type: the rune line** ("lights out": using a rune flips it and its neighbours; world/Puzzles.java:
    15-36; Rooms.pressRune:447-478). It opens a caged cache and, in a Puzzle Vault, the shrine.
  - Also: Hub keys, Friendly-gate lanterns, arena seals, the Double Gate's "law", Stealth Halls, and Sky Archipelago
    updrafts (gates/block/GateBlocks.java:365-377).
- **Missing mechanisms:** no redstone, moving blocks, timed bridges, light beams or gravity rooms. The Collapse Timer
  modifier drops **no blocks** (run/Modifiers.java:293-348).
- **Mirror Palace:** the Mirror Maze is static walls, and gate_mirror isn't in the awaken:mirror tag, so the spirit
  can't walk through gate mirrors as plan.html promised.
- **Reusable machinery:**
  - The Ritual (story/Ritual.java) has beat timelines that catch up after lag, saved-and-restored block swaps (pits
    :898-970), positional triggers (plates :669-722), telegraphs (:762-781), and lights on and off. Its geometry is a
    pure class shared by the painter and the server (gates/world/PiecesRitual.java, gates/RitualHall.java).
  - Elsewhere: Veil gates' lever puzzles, stratum 7's gravity tides (descent/rules/Zones.java:256-310), DreamRooms,
    FlyingBlocks (block-display projectiles) and TerrainLedger.
- **Rules inside gates:**
  - Survival can't break "fabric" blocks (GateEvents.java:200-223), but about 50 decorative Kit and piece blocks
    outside the palettes can be broken.
  - **Placing is allowed.** Architect constructs place freely.
  - Flight drains ×1.5.
  - **Nothing in any gate needs a power or a move.**
- **Access:** no rank or capability requirement to enter (Runs.enter:95-153).
- **Trials** (hearth/trial/Trials.java): waves, duel, the A-rank Descent (hatch drops), and the Sovereign mirror.
  All of them test combat.

## The overworld today

- **About ten systems:** ruins, landmarks, anomalies, fauna and lairs, the Well and the Descent, the Veil, Lucidium
  visions, the Above, the Hearth, terrain heroes. **Nearly all are "walk to a marker, fight or open a chest".**
- **Sky platforms** (above/ruin/PrecursorRuinStructure.java:26,56):
  - fixed at base Y 262–269, deck about Y 275–282, static;
  - signposted from level 20 with "Bring wings." (world/landmark/LandmarkKind.java:23-25);
  - no way up until Jet Boots (road level 37, blueprint luck) or A-rank Flight;
  - **the same loot table as a ground vault**;
  - a block tower counts as reached.
- **Terrain heroes** (Elder Colossus 55–90 tall, Lumen Spire, Gate Scar, Shard Drift floating shards 20–28 up) give
  no loot, discovery or Now line (no Progression calls in terrain/).
- **Anti-cheese:**
  - **No overworld block protection at all.**
  - Rank doors can be dug around: the plating has strength 4 and is mineable by any pickaxe
    (AboveBlocks.java:37-39; src/main/merge/above/data/minecraft/tags/block/mineable/pickaxe.json).
  - The only protection anywhere: Constructs inside Hearths, the Stillpoint and Veil pockets, gate fabric, dreams.
- **The exploration signal is muted:**
  - The HUD draws only the top Now suggestion (signal/client/TrackerHud.java:20,66-69).
  - Priorities: unspent points 55, a gate within 400 m 45, requests 42, landmarks 30.
  - The landmark line picks the nearest landmark, so an unreachable sky platform holds the slot.
  - Mira rarely tells landmark rumours.
- **Counters that feed nothing:** rifts_closed, stars_opened, star_guardians_slain, groves_visited, spirit_caches,
  anomalies_seen, landmarks_reached, lair_heard, precursor_logs_read, precursor_doors_opened. **No directive is about
  exploring.** Biome discoveries were promised in plan-v2 and are not built.
- **Time split:** tools/sim/pacing_sim.py, run in memory (balanced player, 150 runs): about 52% gates and trials,
  48% overworld (10% of it walking to gates). Gates give 54% of XP.
  - The game logs no XP by source (Progression.grantXp:100-110), so the real split is unmeasured.
  - The sim's overworld is one bucket; it doesn't model the Descent, landmarks, lairs, the Veil or mounts.
