## What remained UNVERIFIED

- **Exact kinetic-weapon damage formula.** Read from bytecode as about `ATTACK_DAMAGE base value + floor(relativeSpeed × damage_multiplier)` (speeds look like ×20, blocks/s). The structure is certain; the arithmetic is not decompiled.
- **Compile-level behaviour of NeoForge-patched methods** (`ItemStack.getSweepHitBox`, `canPerformAction`) as seen from mod code. These were read in the patches and sources only. They are not in the vanilla jar and were not compiled here (no JDK 25 / gradle).
- **`IClientItemExtensions.applyForgeHandTransform` and `RegisterSpecialModelRendererEvent` / `RegisterItemModelsEvent` in practice.** The sources were read; there is no repo usage to prove they behave as expected.
- **GeckoLib's own maven coordinates** for 26.3 (Cloudsmith 404). Its Modrinth licence says MIT; the licence in the jar itself was not read.
- **`ItemUseAnimation.hasCustomArmTransform()`**: which values return true was not decoded.
- Nothing was run in game. The behaviour claims (who sees what, the timing of the swing packets) come from code reading only.
