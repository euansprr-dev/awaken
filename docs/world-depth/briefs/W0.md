## Scope (PLAN 5.1 and the audit's change list)
1. **Settlements, not a singleton.** Replace `Citizens.active` with a `Settlement` per place, each holding its ledger,
   street graph (`StreetNet`), saved state, work (`CitizenWork`) and events, registered in one per-server registry.
   Carillon is settlement 0, built from its jar roster and `plan.json` exactly as today (plan hash check kept).
2. **One body pool.** `CitizenBody` carries its settlement id; the world cap (96) and the per-player cap (40) are shared
   by every settlement nearest-first, so a village can never starve the city; path slots shared the same way.
3. **Saved data v2.** `awaken:citizens` becomes a list of settlements, each versioned with its own sizes and district
   count; Carillon's existing save loads into settlement 0 with nothing lost (a test reloads a v1 save).
4. **Coordinates.** World coordinates or a per-settlement origin instead of Carillon's single centre and street height;
   per-node y stays as `StreetNet` has it.
5. **Rosters from code.** A `RosterSource`: Carillon's from the jar; any other settlement's from a Java builder given
   households, workplaces and stations (the data shape `tools/city/citizens.py` produces, built at runtime). W3 writes the
   village builder; you write the interface and a minimal builder for the test settlement.
6. **Events and work by station, not by district constant.** City events pick places by station or plot tags ("a house
   with a door", "near water", "a stall"), so the burglary, fire, cart and pickpocket can happen in any settlement;
   Carillon's own picks stay as they are (its districts map to tags).
7. **Per-settlement names and memory.** Recognition, gossip, speech `{district}` and the soundscape's districts read
   their settlement's own names; skins come from a pool by hash for settlements that aren't Carillon.
8. **Predicates.** Carillon's spawn rule, civic protection and lamps stay Carillon's (`CityHooks.inCity`/`isCivic`); a
   settlement exposes its own `inside(pos)` for W3.
9. **A public API for W3** (SPEC §12): `dev.awaken.citizens.api.Settlements`: `register(SettlementSpec)`,
   `at(level, pos)`, `byId`, `bodies(id)`, plus the `Settlement` view W3 needs (standing per player, a place's
   stations). Keep it small; write it in SPEC.
10. **Proof:** a GameTest builds a tiny test settlement (three houses, a well, a smith, six people with a day) beside
    Carillon's engine, ticks both, checks bodies come and go within the shared caps, and saves and reloads them.

## Budgets (SPEC §16.10 and the audit's constraints)
Ledger ≤ 0.5 ms a tick for all settlements together; bodies ≤ 1.5 ms; no per-tick allocation; next-hop bakes ≤ 3 a tick
across settlements; overworld only; loaded chunks only for runtime edits; citizens are hurt, never killed.
